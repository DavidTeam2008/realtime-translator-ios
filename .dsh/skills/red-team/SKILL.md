# red-team · 独立只读审查

范围：仅 L2 中的**并发、持久化、发布工程**强制独立复核（`AGENTS.md` §7）；其他 L2 用自检清单 + 用户确认，不走本 skill。

## 输入（只给这些）

- 任务描述
- 方案 / 计划文件（含验收与风险）
- 仓库路径
- 可选：diff、evidence 文件
- **不给**：起草过程对话、实现者自评、既往结论性摘要。

## 执行者

- 优先全新上下文：DSH subagent / Agent Teams（用户级启用时），或新会话。
- 只读：不改文件、不读 `.env`、不跑破坏性命令；可跑只读检查（`make verify-static` 等秒级静态命令）。

## 输出（固定结构，写入 `.apm/reviews/`）

1. 结论：可接受 / 需修改 / 阻断。
2. P0/P1/P2 表：问题 | 证据（file:line 或命令） | 影响 | 建议。P0=执行前必须修；P1=修完再合；P2=记录排期。
3. 被挑战的假设：方案默认成立但未证明的点。
4. 缺失信息：需要实现者补充才能判定的事项。
5. 最小验证清单：能证伪 / 证实关键风险的最少命令或演练。

## 闭环

- 作者逐条回应：接受 / 拒绝 / 待定 + 理由；最多两轮。
- P0/P1 必须在执行前解决；P2 记录进计划或 `.apm/issues/`。
- 无独立审查者时：用检查清单自检，并在计划写"未独立审查"；不得声称已完成红队。
- 报告与回应都入库，不要只留在对话里。
