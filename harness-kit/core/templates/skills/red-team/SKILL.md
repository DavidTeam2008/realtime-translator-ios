# red-team

> 触发：并发、持久化、发布 / 迁移，或规则 / 门禁自身的大改。
> 参考：[工作流](../../../{{REFERENCES_DIR}}/workflow.md)、[审查目录说明](../../../{{HARNESS_DIR}}/reviews/README.md)。

## 输入

- 任务描述、方案、仓库路径（含目标 commit / 工作树状态）。
- 不传起草对话、作者自评、既往结论；自行读取当前树。

## 规则

- 只读：不改文件、不跑破坏性命令、不读密钥或 `.env`。
- 每条结论可定位：`file:line` 或命令输出摘要。
- 只报影响正确性、可验证性、可维护性的问题；不做风格偏好争论。

## 输出

1. 结论（通过 / 有条件通过 / 不通过）。
2. P0 / P1 / P2 表：问题 | 证据 / 位置 | 影响 | 建议。
3. 被挑战的假设；缺失信息与待验证项。
4. 最小验证清单（命令 + 期望结果）。
5. 报告从 [`_template.md`](../../../{{HARNESS_DIR}}/reviews/_template.md) 复制，命名 `<YYYY-MM-DD>-<topic>.md`。

## 收尾

- 作者逐条回应（接受 / 拒绝 / 待定 + 理由），最多两轮。
- P0/P1 执行前解决，P2 记录排期；回应写回报告或计划。
