# AGENTS.md · docs/

> 触发：修改或新增 `docs/*.md` 前先读本页。
> 本页只写文档目录的增量规则；文档索引与真源优先级见 [`README.md`](README.md)，项目规则见 [`../AGENTS.md`](../AGENTS.md)。

## 1. 当前规范与历史记录

- `01`–`04` 是**当前规范**：01 产品行为、02 架构与数据链路、03 技术选型、04 问题/验收/排期；`decisions.md` 是唯一决策表。
- `case-*.md` 是**带证据的案例**（不是规范）：只写结论、口径与可复核线索；历史过程文档已蒸馏，原始记录见 git 历史。
- 不恢复已退休的 `05`–`13` 与 `14`–`21` 编号；历史文档不再重写为当前文档。

## 2. 真源优先级

- 真源优先级只在 [`README.md`](README.md) 写一次；本目录其他文档不重复声明。
- 代码与测试是事实源；文档与代码冲突时以代码/最新验证为准，并顺手修正文档。
- 规则不写进 docs：规则放根 AGENTS / `references/`；docs 只写事实与理由。

## 3. 写哪一篇

- 产品行为 → `01`；分层/依赖/数据链路/并发/持久化 → `02`；框架选型、明确不选与理由 → `03`；问题、验收判据、排期 → `04`（唯一排期源）。
- 决策表唯一源是 [`decisions.md`](decisions.md)（D1–D7）；其他文档只引用 ID。
- 测试计数唯一源是 [`../references/verification.md`](../references/verification.md)；docs 里用“见 verification”引用，不复写数字。
- 跨会话/交接 SOP → `CONTRIBUTING.md` + `.dsh/skills/handoff`（active 计划是状态唯一源）；修复记录用“发现 → 红测 → 修复 → 绿测 → follow-up”格式。

## 4. 新增与索引

- 新增 `docs/*.md` 必须登记到 [`README.md`](README.md) 的索引表，否则 `make check` 失败。
- 命名：当前规范用 `NN-topic.md`；专题文件用 `decisions.md` / `case-*.md`（不加编号，必须登记索引）。
- 新当前规范先确认归属（多数情况应并入 01–04，而不是新建重复文档）。

## 5. 链接与格式

- 只用相对链接；Linux CI 大小写敏感；不写本机绝对路径或设备信息。
- 代码围栏成对闭合（check-docs 会拦）；引用代码优先写类型/函数名，少写行号（易漂移）。
- 案例中的数字保持当时口径；需要更新结论时新增带日期段落，不改写历史证据。

## 6. 验证

- 文档改动跑 `make check`（`check-docs`：链接/围栏/索引/预算）；失败先修链接与索引，不靠删内容变绿。
- 只改事实，不扩写；同一事实只在一个真源维护，其余引用。
