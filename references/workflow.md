# 任务分级、长任务与红队

> 触发：方案设计、L2 改动、跨会话任务、接手、红队审查时读。

## L0 / L1 / L2（本项目口径）

| 级别 | 例子 | 动作 |
|---|---|---|
| L0 | 文档/注释、单测补充、单文件纯函数、明显笔误、只读排查 | 直接做；跑最小验证 |
| L1 | P1-1~P1-3、局部行为修复、单模块测试补充 | 5–10 行短方案 + 验收；直接做 |
| L2 | P0-1 gate、P0-2 留存、P0-3 SwiftData/迁移、发布/签名/CI、跨模块重构 | 完整方案 + 用户确认；仅并发/持久化/发布工程强制独立复核，其他 L2 自检 + 确认（AGENTS §7） |

L1 方案写 5–10 行（目标、改动点、验收）；分级入口由 AGENTS §3 路由到本文件，判断以本表为准，不确定按 L1。L2 方案按风险裁剪：目标/非目标、约束/假设、设计、备选、验收、风险/回滚、验证计划、待定问题。

## 计划与检查点

- 任何预计跨会话的任务（含 L1、含接手）用 `make plan TOPIC=<topic>` 起稿；会话内任务列表只作视图。
- `make handoff` 取 active 计划（`PLAN=<path>` 可指定）；交接前更新进度、已排除、验证证据、未提交改动、下一步。
- 检查点 = 可恢复快照：commit（需确认）或 patch/备份 + 已验证状态；回滚前先保存未提交改动，不要 `reset --hard`。
- 改语音前留真机基线；改持久化前备份样例；改迁移先写迁移测试。

## 红队（只读）

- 范围：仅并发、持久化、发布工程强制独立复核；其他 L2 用自检清单 + 用户确认。
- 执行：general-purpose 子 Agent 或新会话；只读、不改文件、不读 `.env`、输入只有任务 + 方案包 + 仓库路径；不传起草对话/自评/既往结论。
- 输出：结论；P0/P1/P2 表（问题 | 证据/位置 | 影响 | 建议）；被挑战假设；缺失信息；最小验证清单。
- 主 Agent 逐条回应（接受/拒绝/待定 + 理由）；最多两轮；P0/P1 执行前解决，P2 记录排期。
- 无子 Agent 时用新会话兜底。
