## 2. 新发现的问题（按影响排序，均已提 issue）

### 2.1 verify.yml 模板浅克隆导致 CI 上 check-plan-strict 必红（P1）

- **issue**：<https://github.com/DavidTeam2008/harness-engineering-kit/issues/4>
- **现象**：barra 推送后 GitHub Actions `verify` 首次运行失败：归档计划的 `submitted` 短 hash 与证据 `git.commit` 在浅克隆里不存在 → `check_plan --strict` 报 11 个 error；本地（全历史）全绿。
- **实证**：barra run `43736616883` failure；补 `with: fetch-depth: 0` 后 run `43736736196` success（宿主提交 `01a51b5`）。
- **建议**：模板 Checkout 默认 `fetch-depth: 0`，或浅克隆时把该错误降级为带修复提示的 WARN。

### 2.2 core/tools/check_plan.py 漏 `import fnmatch`（P1）

- **issue**：<https://github.com/DavidTeam2008/harness-engineering-kit/issues/5>
- **现象**：v0.5.2 的 `check_plan.py` 在 scope 通配符分支调用 `fnmatch.fnmatch` 但未 import；barra 升级后项目 CI ruff `F821`，且该分支一旦执行会 NameError。
- **实证**：barra 升级提交 `d3630d4` → CI run `43736616910` lint failure；补 import 后 `ruff` 全通过（`01a51b5`）。barra 0.3.0 时期本地补丁 `fa53753` 被升级覆盖，属回归。
- **建议**：上游补 import；kit 测试增加走通配符 allow 分支的用例。

### 2.3 HARNESS.md 模板预算无余量（P2）

- **issue**：<https://github.com/DavidTeam2008/harness-engineering-kit/issues/1>
- **现象**：0.5.2 模板约 **1491/1500 tokens**。fcnsystem 的 118 tokens JUnit 例外说明无法保留（1494+118=1612）；barra 的 44 tokens 例外同样放不下（1491+44=1535），只能改为「保留宿主 HARNESS + 手工移植 0.5.2 语义」，升级后该文件为 LOCAL_ONLY。
- **建议**：模板继续瘦身（证据政策细节下沉 evidence README）或提高默认预算；`--plan` 对 CONFLICT 行输出 tokens/预算/余量。

### 2.4 `.gitignore` 追加块去重导致假 CONFLICT（P2）

- **issue**：<https://github.com/DavidTeam2008/harness-engineering-kit/issues/2>
- **现象**：`harness-init` 对已有 `.gitignore` 去重后写入块并记 manifest sha；`--plan` 在空目录渲染出未去重块 sha → 两 sha 必不同，宿主无论如何都显示 CONFLICT。本轮两家宿主按「模板全量块」写入（接受与宿主重复的 `node_modules/` 等）才收敛。
- **建议**：plan 侧按宿主现有内容去重后比较，或 manifest 同时记录模板块/去重块，或比较块指纹。

### 2.5 归档证据与 done 计划引用冲突（P2）

- **issue**：<https://github.com/DavidTeam2008/harness-engineering-kit/issues/3>
- **现象**：fcnsystem 按政策把旧证据移入 `harness/evidence/_archive/` 并让新证据 `supersedes` 后，`verify_claim --fresh --strict` 变绿（2 PASS + 2 SUPERSEDED）；但 `check_plan --strict` 对仍引用旧证据的 done 计划报「证据 ID 不存在」，只能把 legacy 计划改成 `status: archived` 才能恢复 strict PASS（语义有损）。
- **建议**：证据加载回退查 `_archive`，或输出明确迁移提示；playbook 迁移矩阵补一条。

## 3. 升级路径可复用结论

1. 先只读 `--check` / `--plan`，用 v0.5.2 tag 渲染临时树逐文件 diff；UPGRADE/ADD 直接回写，CONFLICT 逐个人工合并，**不要整文件覆盖宿主文档**。
2. 大版本跨级（0.3.0 → 0.5.2）必须同时执行 playbook 的「v0.3.0 → v0.4.0 迁移矩阵」：归档计划补「未验证豁免 / 提交范围例外」，当前 PASS 证据 `supersedes` 归档 UNVERIFIED 证据，`.gitignore`/配置/预算按新版合并。
3. manifest 基线用新版 init 渲染结果，宿主定制文件保持 LOCAL_ONLY；`--check` 的 exit 1（本地漂移）是预期语义，升级完成以 `--plan` 无 UPGRADE/CONFLICT/ADD/OBSOLETE 为准。
4. 升级后必须重跑 `make selftest`（证明门禁仍会红），并至少刷新一次可本地重跑的静态证据；测试类证据若需服务器环境，按未验证 + 豁免处理并写清到期日。
