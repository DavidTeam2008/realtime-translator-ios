## 1. 结论摘要

- **可执行性**：方案结构（E/O/P 写作用域、V1–V12 决策、验收 §6）基本可落地；实现已在并行推进，说明粒度可执行。
- **不可直接冻结的原因**：核心承诺是"绕过路径被封"，但当前设计有 5 个 P0 级绕行（归档免检、证据静默消失/缺失 claim、submitted allowlist 自放宽、多环境可挑宽松环境、artifact 未绑定）；其中"归档降级 WARN"与反馈 P0-1/P0-2/P0-3 的修复目标直接冲突。
- **发布门禁语义**：v0.4 门禁可证明"仓库内部自洽 + 声明的 artifact 能按当前文件重算"，**不能**证明测试真实执行、执行环境、独立评审、waiver 合法性或 allowlist 未被放宽；这一点必须写进 README/SPEC 的"局限"，否则发布门禁仍会被误读为"完成可信"。
- **对决策的建议**：先修 §2 的 P0-1…P0-5（含对应负向测试入 kit tests 与 barra fixture 期望），再按 §7 清单冻结；P1 可在 v0.4.0 同批修，P2 排后。

## 5. 被挑战的假设

1. **"归档降级 WARN 不会削弱门禁"**：归档是普通 `git mv`，没有前置校验；先归档即可跳过顶层 done/active/submitted 硬检查（P0-1）。
2. **"SUPERSEDED 输出 = 审计链保留"**：不参与退出码、无 ledger、无 required claims；移动/删除证据仍绿（P0-2），审计链只在日志层而非状态层。
3. **"submitted 增量审计 + 当前 scope.allow 就能封越界"**：scope 可在 plans 过程目录自改（且审计用当前值）；merge diff 命令本身写错（P0-3/P1-1）。
4. **"environment model 解决多环境误判"**：环境字段自报、只对 skipped 做容差、floor 仍全局、required claims 未强制；能防手滑，不能证明环境（P0-4）。
5. **"JUnit 默认脱敏 = 可安全入库"**：只处理 XML；evidence JSON environment 可含服务器 IP（barra 实例）；keep-raw+outside-root 生成不可验证证据（P1-2/P1-3）。
6. **"scorecard 自动生成 = 独立复评可追溯"**：工具只生成自评草稿；独立列 TBD、check 仅 WARN、release 不阻断（P1-6）。
7. **"v0.4 发布门禁 = 完成可被证明"**：门禁证明的是"仓库内部自洽 + 当前 artifact 可按当前文件重算"，不证明测试真实执行、执行环境、评审独立性、waiver 合法性（见 §1 发布门禁语义）。

## 7. 最小验证清单（冻结前必须全绿；命令可在临时 fixture/临时 clone 上执行，不写被审查仓）

1. **merge 语义**：临时 git 仓造 merge（main 侧新增 out-of-scope 文件、分支侧修改 in-scope 文件）→ `git diff --name-only <merge>^1 <merge>` 与方案命令对比，断言 scope 审计只用第一父 diff；kit 测试加 `test_submitted_scope_merge.py`。
2. **allowlist 自放宽**：fixture 中提交 `foo/out.py`（不在 allow）→ 在计划加 `foo/`/`scope.exceptions` → 将两提交写入 `submitted` → `python3 harness-kit/core/tools/check_plan.py check --root <fixture>` 必须 exit 1（修复后）；同一测试覆盖"计划在提交后才改 allow"。
3. **归档逃逸**：active 计划带越界 submitted → `git mv` 到 `_archive` → `check_plan check` 必须 exit 1；done+未验证项→归档也必须 exit 1（legacy 白名单除外）；`archive` 目录中 status=active 必须 exit 1。
4. **证据移动/删除**：复制 barra 到临时目录（只读 clone）→ 把 `harness/evidence/_archive/20261111T073858Z-tests-pass.json` 从当前/归档位置移动/删除，`python3 tools/verify_claim.py --all --root <copy>`：无合法 supersedes 时必须非 0；删掉 tests-pass 当前证据只剩 docs-pass 时必须输出缺失 claim 的 UNVERIFIED（exit 2）。
5. **artifact 绑定**：sanitize-copy 产物不 `git add` → verify-claim 必须 UNVERIFIED；artifact 内容替换但 evidence 的 sha256 不匹配 → FAIL；`--keep-raw --allow-outside-root` → exit 2 或 UNVERIFIED（不能 PASS）。
6. **waiver**：done 计划 3 条未验证 + 单行 `item=pytest, reason=x, owner=self, expires=2099-12-31` → exit 1；合法 waiver（含 `approved_by`≠owner、review 来源、到期≤90 天、逐条覆盖）→ exit 0；过期 waiver → exit 1。
7. **多环境**：config 两个 claim（server/ci，`environment.id` + `floorByEnvironment`）；只交 ci 证据 → server claim UNVERIFIED；ci 证据 passed=238 vs server floor=290 且 env=ci → 不出现假 FAIL（按 env floor 判）；`byEnvironment` 未命中 → UNVERIFIED；evidence environment 缺 id → UNVERIFIED。
8. **layers untracked**：fixture 造未跟踪 `barra/bad_layer.py` 违规 import → `check_layers --root` 必须 WARN/FAIL（修复后 FAIL）；`git add` 后仍违规；规则 matched=0 时 `--strict` FAIL。
9. **JUnit 脱敏**：fixture XML 含 hostname、system-out、failure message 绝对路径、property 本机路径 → 生成产物 grep 无泄漏且 recount 与原始 counts 一致；`--xml` 指 symlink / 6MiB 文件 / artifacts dir 为 symlink → exit 2；evidence JSON environment 无 IP/主机名（barra archived evidence fixture）。
10. **迁移 dry-run**：临时 clone barra@`bab9ac6` + v0.4 候选 kit → `python3 harness-kit/scripts/harness-upgrade --plan ...`（只读、临时目录）与 `make check`/`verify-static`/`verify-claim` 新行为输出矩阵；断言：预期红/绿/WARN 与迁移矩阵一致、无仓库写入；barra archived 证据 IP 处理有结论。
11. **scorecard/发布**：standard fixture 生成 scorecard → 独立复评列 TBD 时 `make release`（strict 模式）必须非 0；过期（改 commit/日期）→ WARN/FAIL；`--generate` 不自动填分数。
12. **发布门禁语义测试**：手工构造与真实 JUnit 计数一致但非测试产出的 XML → 记录当前 verdict；在 README/SPEC 写入"能证明/不能证明"清单（或实现 CI provenance 后升级测试）。
